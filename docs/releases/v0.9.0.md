## UntuShot 0.9.0

UntuShot now saves editable screenshots automatically and opens GNOME captures
directly in the editor. This release also simplifies the interface and fixes
capture cancellation, error dialogs and installation from Snap-based terminals.

### Capture once, start editing

- On GNOME, New Screenshot and Ctrl+Shift+X open the desktop capture chooser
  directly, including when UntuShot is not already running.
- Confirmed desktop captures enter the editor immediately; no second region
  selection is required. Cropping remains available as an editing tool.
- Cancelling GNOME's chooser no longer opens an error dialog. The existing image
  is preserved; GNOME's ambiguous no-image response produces a neutral status.
- The tray offers one capture action, an optional three-second delay before
  opening the chooser, the editor and Quit. Cancel appears during capture.
- Direct grim capture retains separate capture modes and monitor selection.
- Capture errors use dismissible, non-blocking dialogs and no longer prevent
  quitting UntuShot.

### Editable work saves automatically

- Saved screenshots get an editable sidecar such as `Screenshot.png.untushot`.
  Reopening the image restores its matching layers and crop.
- Edited captures without a filename get a uniquely named project in
  Pictures/Screenshots or the configured export folder. Named projects save in place.
- Switching images and quitting finish saving without routine project-save prompts.
  Save Project As remains available for separate copies.
- Background saving preserves explicit PNG exports. Failed writes and external
  file conflicts are reported, with recovery data retained.
- Recovery preserves the project's automatic-save destination across restarts.

### A calmer workspace

- Compact capture options, clearer save status and keyboard navigation.
- The empty layer panel stays out of the way and opens when needed.
- Resizable layer/property areas and more consistent help and error windows.
- Updated English, German, French and Spanish interface text.
- Refreshed feature recordings show the current controls, automatic sidecars
  and simplified GNOME capture workflow using synthetic images.
- The source installer removes inherited Snap GTK resource paths even when the
  `SNAP` variable is missing, preventing the reported GLIBC startup crash. Startup
  failures report the actual process error instead of blaming tray support.

### Downloads

**x86-64 / amd64 only.** Built on Ubuntu 22.04 (glibc 2.35).

Debian package for Ubuntu 22.04+ and Debian 12+:

```sh
sudo apt install ./untushot_0.9.0_amd64.deb
untushot
```

AppImage for compatible Linux desktops with glibc 2.35 or newer:

```sh
chmod +x UntuShot-0.9.0-x86_64.AppImage
./UntuShot-0.9.0-x86_64.AppImage
```

Without FUSE, use `APPIMAGE_EXTRACT_AND_RUN=1 ./UntuShot-0.9.0-x86_64.AppImage`.
Download both packages and `build-info.json`, then run `sha256sum -c SHA256SUMS`
to check their integrity. No signing key is configured.

Packages provide application launchers; global shortcuts and login autostart
remain desktop settings. Tray icons require desktop AppIndicator support.
Editable projects include the original image, including cropped or covered
content; share the exported PNG when only the visible result should be shared.

The release pipeline runs optimized Rust/security tests, installer checks,
four-language GTK checks, editing/layer/clipboard workflows, portal cancellation,
error dismissal and automatic-save regressions. Both packaged editors are also
started on an isolated display and checked for version, language and integrity.
Real mixed-DPI capture and tray behavior remain dependent on the desktop.
