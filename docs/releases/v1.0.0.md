## UntuShot 1.0.0

UntuShot 1.0 completes the core screenshot editing workflow with an editable
background layer, layer locking, selection deletion and bucket fill. Transparent
areas are visible on a checkerboard, and adjustable fill tolerance makes it easier
to recolor connected areas with slight color differences.

### Every image is a layer

- The original screenshot or opened image appears as a **Background** layer.
  Move, resize, hide, duplicate, reorder, rename or delete it like other image
  layers. Moving or deleting it preserves the canvas size and reveals transparency.
- Each layer has a padlock control. Locked layers cannot be edited, moved,
  resized, renamed, reordered or deleted, and canvas clicks skip them.
  Select their row in the layer list to unlock them.
- Visibility remains available on locked layers, and duplicating one creates
  an unlocked copy. Group edits leave locked members unchanged.
- Locks support undo/redo and persist in editable projects, automatic sidecars
  and session recovery.

### Delete selections and fill connected areas

- Use **Selection** (`M`) to mark a rectangle, then press `Delete` or use
  **Delete selection** to clear its visible content.
- Use **Fill** (`F`) to fill a connected area, including transparent space,
  with the current color.
- **Tolerance** ranges from 0% for exact matches to 100% for all colors.
  Matching compares each pixel with the clicked color, including opacity,
  and stays within the connected area. The last tolerance is remembered.
- Both actions respect the crop, support undo/redo and persist in projects.
  Deletions retain the underlying layers; fills add a new image layer.
  They act on the visible composite and can cover locked layers without
  changing those layers.

### See transparency while editing

- A checkerboard shows fully and partly transparent canvas areas and adapts
  to the light or dark interface theme.
- The checkerboard is editor chrome: exported PNGs, clipboard images and
  fill sampling retain the actual pixel transparency.
- New controls include English, German, French and Spanish translations.

### Project compatibility

Existing projects remain readable and gain an editable background layer when
needed. Version 1.0 writes project format 7, which preserves layer locks;
older UntuShot versions cannot open these newly saved projects.

Editable projects retain the original image, including cropped, cleared or
covered content. Share the exported PNG when sharing only the visible result.

### Downloads

**x86-64 / amd64 only.** Packages target Ubuntu 22.04 (glibc 2.35).

Debian package for Ubuntu 22.04+ and Debian 12+:

```sh
sudo apt install ./untushot_1.0.0_amd64.deb
untushot
```

AppImage for compatible Linux desktops with glibc 2.35 or newer:

```sh
chmod +x UntuShot-1.0.0-x86_64.AppImage
./UntuShot-1.0.0-x86_64.AppImage
```

Without FUSE, use `APPIMAGE_EXTRACT_AND_RUN=1 ./UntuShot-1.0.0-x86_64.AppImage`.
Download both packages and `build-info.json`, then run `sha256sum -c SHA256SUMS`
to check their integrity. No signing key is configured.

Packages provide application launchers; global shortcuts and login autostart
remain desktop settings. Tray icons require desktop AppIndicator support.

### Release checks

The release pipeline includes optimized Rust/security tests, installer checks,
four-language GTK checks, editor/layer/clipboard workflows, portal cancellation,
capture errors, automatic saving and the new background, locking, transparency
and fill workflows. Packaged startup checks run on a private desktop session
with sufficient shared memory. Release output directories retain host ownership
so CI can stage release notes alongside the generated packages.

Real mixed-DPI capture, monitor hotplug, compositor permissions and tray behavior
still require acceptance testing on the target desktop.
